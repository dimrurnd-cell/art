# Онлайн-каталог художников «Арт-Ростов»

Встраиваемый виджет для сайта https://арт-ростов.рф/ru/ (Django, вставка через Snippet).
Реализован по ТЗ `../ТЗ_онлайн-каталог_Арт-Ростов.md`.

## Состав

```
catalog/
├── snippet.html               ← код для вставки в Snippet
├── demo.html                  ← локальный предпросмотр (без сервера заявок)
├── static/artcatalog/         ← статика виджета (выкладывается на сайт как есть)
│   ├── catalog.css            ← стили (все классы с префиксом .artc-)
│   ├── hall.css               ← стили виртуального зала (3D-тур)
│   ├── catalog.js             ← логика (vanilla JS, без зависимостей)
│   ├── gallery.js             ← WebGL-галерея (собирается из gallery/, грузится по требованию)
│   ├── artists.json           ← данные художников
│   ├── fonts/parangon.woff2   ← фирменный шрифт Parangon
│   ├── curator/               ← куратор: faq.json (готовые ответы), kb.md (сведения
│   │                             для нейросети), figure.webp (фигура), face.webp (портрет)
│   └── img/                   ← оптимизированные изображения (WebP + JPEG)
│       ├── logo.webp/.png
│       └── <художник>/avatar.*, workN-400.*, workN-800.*, workN-1600.*
├── tools/prepare.html         ← подготовка художников прямо в браузере
├── tools/build-atlas.html     ← атлас превью для 3D-галереи (atlas.json + img/atlas/)
├── tools/prepare-artists.py   ← то же самое из командной строки
├── tools/curator-anim.py      ← движение куратора: цикл из кадров ролика (idle.mp4, idle.webp)
├── gallery/                   ← исходники WebGL-галереи (three.js), сборка: npm run build
├── django/artcatalog/         ← Django-приложение: заявки «Хочу купить» и ответы куратора
├── tilda/                     ← версия для Tilda: статика с CDN jsDelivr
└── server/                    ← версия для Tilda: статика со своего сервера
```

Для установки на Tilda есть два варианта размещения статики:

- **`server/README.md` — рекомендуемый.** Файлы лежат на собственном сервере:
  обновление контента сводится к перезаливке файла, доступность под вашим
  контролем. Есть режим, которому не нужна вообще никакая настройка сервера.
- `tilda/README.md` — раздача через бесплатный CDN jsDelivr прямо из этого
  репозитория: ничего не нужно выкладывать, но версия закреплена хешем коммита,
  а сам сервис зависит от провайдера — у части из них он блокируется, и на
  «холодных» узлах CDN (например, при работе через VPN) те же адреса могут
  отдавать 404. Годится как запасной источник.

Заявки в обоих случаях принимает попап-форма Tilda (Django-бэкенд не нужен).

## Настройки виджета (атрибуты контейнера)

| Атрибут | Назначение |
|---|---|
| `data-base` | адрес папки со статикой |
| `data-tilda-popup` | имя попап-формы Tilda для заявок (открывается щелчком по ссылке `#popup:…` — Tilda слушает такие щелчки на всей странице; во весь экран зал сначала сворачивается — и 3D, и простой, — иначе попап оказался бы под ним; пока попап появляется, кнопка пишет «Открываем форму…») |
| `data-ticket-url` | ссылка кнопки «Купить билет» на дальней стене зала |
| `data-endpoint` | приём заявок своим бэкендом (вместо попапа Tilda) |
| `data-policy` | ссылка на политику обработки персональных данных |
| `data-hall` | вид зала: `webgl` — 3D-галерея, `css` — простой зал (стена с работами, без WebGL); пусто — выбор по устройству |
| `data-curator` | адрес куратора на своём сервере, например `https://donexpocentre.ru/api/artcatalog/curator/` (нейросеть GigaChat); без него куратор отвечает готовыми ответами из `curator/faq.json` |
| `data-curator-name` | имя куратора в заголовке окна вопросов (без него — «Куратор выставки») |

## Разделы выставки

Художников можно разложить по разделам — в зале это отдельные коридоры с
переключателем, в карусели — отдельные списки. Раздел указывается полем
`section`, названия и порядок задаются списком `sections`:

```json
{
  "sections": [
    { "id": "art-salon", "title": "Арт-салон" },
    { "id": "galerei",   "title": "Галереи" }
  ],
  "artists": [
    { "id": "volvich", "section": "art-salon", "...": "..." }
  ]
}
```

Без `sections` каталог работает как раньше — один общий коридор.

Работы показываются все, сколько бы их ни было: в зале они занимают столько
пролётов, сколько нужно (по две на пролёт, слева и справа), в карточке
художника — сетку.

### Поиск и указатель по буквам

В каталоге над каруселью — поле поиска (по фамилии и городу) и ряд букв:
нажатие на букву оставляет только тех, чья фамилия на неё начинается,
повторное нажатие снимает отбор. Показываются только буквы, которые в
разделе есть. Рядом счётчик: «5 из 123».

В зале то же самое живёт в панели, которая открывается кнопкой со списком
художников: поиск, буквы и переход прямо к нужному залу.

Это не украшение, а необходимость: 123 художника в одном коридоре — это
210 000 пикселей пути, полторы сотни шагов из конца в конец. Поэтому же в
разделе больше десяти художников ряд фамилий под залом заменяется кнопкой
со списком и поиском: ряд из 123 кнопок занял бы четверть экрана.

## Режимы просмотра

- **3D-галерея (WebGL)** — режим по умолчанию там, где браузер умеет WebGL.
  Здание из холла и залов в светлом минималистичном стиле: белые стены,
  светло-серый пол из микроцемента, световые линии в потолке, трековые
  споты над каждой работой, тонкие чёрные рамы из багетного профиля с мягкой тенью, надписи
  современным гротеском прямо по стене. В холле белая стойка, скамьи из
  светлого дуба, логотип, название выставки («Купить билет» ведёт по
  `data-ticket-url`) и по проёму на каждый раздел; в проёме виден сам зал.
  **Реалистичная картинка.** Материалы физически корректные (PBR): у пола из
  полированного микроцемента, окрашенной штукатурки стен и потолка, дуба
  скамей, шлифованного металла треков и холста картин есть рельеф и
  шероховатость — фактуры делает генератор `gallery/tools/gen-textures.py`
  (бесшовные, 2048 px для компьютера и 1024 для телефона, ~11 МБ, лежат в
  `static/artcatalog/gallery-assets/`). Отражения — от самого зала: при входе
  в помещение кубическая камера снимает его, и пол, рамы и металл отражают
  картины и свет на своих местах (коррекция по коробке комнаты). Свет —
  16 настоящих спотов на компьютере (6 на телефоне) над ближайшими работами,
  у четырёх ближайших мягкие тени рам; споты плавно перетекают к новым работам
  при ходьбе. В холле — площадные источники в потолочных панелях. На высоком
  качестве — свечение ламп и линз, объёмное затенение, виньетка и зерно.
  **Споты не пересвечивают работы**: цвет картины всегда берётся из
  изображения, а свет спота лишь слегка меняет яркость — в пределах −15…+12 %
  (замер на однотонной картине: белое у верха 1.01–1.03 от исходного вместо
  1.6, средние тона в пределах ±10 %). На высоком качестве картины заранее
  проходят обратное преобразование к тон-маппингу кадра, поэтому и там их
  цвета не сжимаются. Пятна света остаются на стене вокруг работы, как в музее.
  **Естественный свет** — кнопка с лампой над сценой: споты плавно гаснут
  (вместе с конусами лучей), зал освещён ровно, а картины показываются в
  цветах исходных изображений — без бликов, пересвета и тон-маппинга (цвет
  пикселя на экране совпадает с исходным). Повторное нажатие возвращает
  выставочный свет; выбор запоминается в браузере (ключ `artg-light`).
  В лучах спотов видны световые конусы (летающую пыль убрали — отвлекала).
  **Музыка и звук** (пункт меню «Музыка и звук», выбор запоминается,
  ключ `artg-sound`): тихая классическая музыка — фортепиано, 7 пьес по
  кругу, начиная со случайной (Сати, Бах, Шопен ×2, Дебюсси, Бетховен ×2;
  записи в общественном достоянии или CC0 с Wikimedia Commons, исполнители
  и ссылки — `static/artcatalog/music/CREDITS.txt`). Файлы MP3 96 кбит/с
  (играют в любом браузере), громкость выровнена (~−23 LUFS), в зале —
  30 % (`MUSIC_VOL`); грузятся по одной пьесе, только когда звук включён.
  Музыка идёт через Web Audio (на iPhone громкость `<audio>` не меняется),
  поэтому файлам нужен CORS — как и картинкам. В начале пьесы — её
  название подсказкой; вкладка спрятана — пауза. Шаги — еле слышный
  шорох по пройденному пути; эхо — только у дверей и щелчка света.
  Прежний синтезированный фон помещения убран: звучал как метро.
  В простом зале — та же музыка кнопкой с нотой сверху; выбор общий с
  3D-галереей.
  **Мебель, оборудование и движение** (`gallery/src/props.js`, всё
  процедурное, без файлов моделей). В каждом зале — дубовые скамьи у торцов
  острова (маршруты их обходят), на перегородках — шкаф с огнетушителем за
  стеклом и знак над ним, гигрометр с показаниями; на потолке — решётки
  вентиляции, спринклеры, датчики дыма с мигающим светодиодом, камера
  наблюдения, которая медленно поворачивается; у выхода — светящийся
  указатель «Выход». В холле — стеклянные раздвижные двери в проёмах
  разделов (разъезжаются, когда к ним подходишь, с шорохом привода),
  кинетическая скульптура-мобиль под потолком (коромысла с дисками качаются
  и вращаются), светодиодный экран на северной стене (заставка: работы
  выставки сменяются каждые 7 с поверх фирменного градиента, с именем
  художника; экран подсвечивает пол и стены), киоск с планом, стойка с
  буклетами и монитор на ресепшене, урны, матовые двери входа. Свет по
  датчику движения: зал, где стоит зритель, освещён полностью, соседние
  приглушены; при входе споты и световые линии загораются волной от входа,
  со щелчком реле. Камера «живая»: при ходьбе чуть покачивается в такт
  шагам, на месте едва заметно «дышит»; в экскурсии и при перелётах — нет.
  Листья растений шевелятся от вентиляции. Вся непрозрачная мебель зала —
  один меш с одним материалом (цвет, шероховатость, металличность и
  свечение записаны в вершины), поэтому вызовов отрисовки в залах всего на
  10–17% больше, чем без мебели; в холле — на ~50% (подвижные двери, мобиль
  и экран рисуются отдельно).

  Раздел — анфилада залов по 25–30 м (в «Арт-салоне» их 24, по 4–6
  художников). Посередине зала свободностоящая стена-остров, работы висят
  на четырёх плоскостях: наружных стенах и обеих сторонах острова. Раздел
  устроен кольцом: вглубь по левому проходу, обратно к холлу по правому, так
  что путь вдвое короче одного коридора и в конце не приходится идти назад
  мимо увиденного. Залы разделены стенами с двумя проёмами; над проёмами —
  «ЗАЛ N» и фамилии художников в нём, на торце острова — номер зала. Над
  работами каждого художника — его имя и город, у каждой работы — этикетка.
  Дальние залы тают в светлой дымке.
  - **путь зрителя**: загрузчик → холл → арка → зал → подход к картине → работа
    во весь экран → карточка художника → «Хочу купить». Заставки с кнопкой нет:
    когда блок галереи подходит к экрану, сразу начинается загрузка (сама сцена —
    отдельный `gallery.js`, ~290 КБ в gzip, поэтому тем, кто не долистал до
    галереи, она не грузится). Загрузчик — песочные часы, песок пересыпается по
    ходу загрузки; рядом проценты, этап («Загружаем 3D-движок», «Развешиваем
    картины и ставим свет») и сколько примерно осталось (по темпу последних
    секунд). Закрыл работу — камера отступает на шаг, и можно идти дальше;
  - **переход между залами** — через холл: вывеска над аркой, кнопка «Холл»,
    табличка «Вернуться в холл» в конце зала, вкладки разделов над сценой.
    Далёкий переход (через весь коридор) идёт через короткое затемнение;
  - **управление**: перетаскивание — осмотреться; W/S или стрелки — идти,
    A/D — шаг вбок, Q/E и ←/→ — поворот, Shift — быстрее, колесо — вперёд и
    назад; щелчок по полу — дойти туда, по картине — подойти к ней, второй
    щелчок (или Enter) — открыть; по этикетке — карточка художника. На
    телефоне — те же жесты и кнопки шага внизу сцены;
  - **«План»** — схема здания (холл, разделы, залы; красная точка — где вы)
    и список залов с фамилиями: нажатие по залу на схеме или в списке ведёт
    туда. Над сценой подпись «Арт-салон · зал 3 из 24» и имя художника,
    у чьих работ вы стоите;
  - **ссылки на место**: адрес страницы сам меняется на
    `#artc-work=<художник>/<номер работы>` у работы и `#artc-room=<раздел>/<зал>`
    в зале (через `history.replaceState` — история браузера не засоряется,
    чужие якоря страницы не трогаются). Кнопка со скрепкой копирует ссылку, на
    телефоне — открывает «Поделиться». По такой ссылке галерея открывается
    сразу, без заставки, в нужном месте;
  - **маршруты** обходят остров и идут через проёмы по осям проходов; на
    другую сторону острова камера переходит у его торца. Проверка
    автотестом: шесть маршрутов (холл → залы, между сторонами острова, в
    соседний раздел, обратно в холл) ни разу не заходят в стену;
  - **«Художники»** — список с поиском по фамилии и городу: переход прямо
    к работам художника в любом зале;
  - **картинки без пустых рам**: при входе грузится атлас превью —
    две-три картинки 2048×2048, где лежат мелкие копии всех работ (около
    0.8 МБ на 581 работу). Сцена проявляется, когда он готов, и с этого
    момента у каждой работы есть изображение. Ближе 45 м работа получает
    400 px, ближе 10 м — 800, вплотную (3 м, у работы, к которой подошли) —
    1600. Вверх переходим сразу, вниз — с запасом по расстоянию, и старая
    картинка висит, пока не пришла новая. Декодирование — `createImageBitmap`,
    вне основного потока; после выгрузки в видеопамять растр закрывается.
    Лимит видеопамяти на крупные картинки — 300 МБ (телефон — 110); при
    превышении до атласа опускаются работы, дольше всех не попадавшие в кадр.
    Нагрузочный прогон на 581 работе (весь «Арт-салон» туда по левому
    проходу и обратно по правому, потом ещё полпути, ~7.5 м/с): пустых рам
    в кадре — 0, пик видеопамяти — 168 МБ на компьютере (84 МБ на эмуляции
    iPhone в прежней планировке), плюс ~43 МБ постоянного атласа;
  - **атлас собирается** страницей `tools/build-atlas.html`: открыть её,
    указать папку каталога (локальную или на сервере — нужен CORS), скачать
    `atlas.json` в корень папки каталога и `atlas-N-xxxxxxxx.webp` в `img/atlas/`
    (в имени — отпечаток содержимого, поэтому долгий кеш картинок не мешает).
    Пересобирать после каждого изменения состава работ. Без атласа галерея
    работает, но у дальних работ до подгрузки видна пустая рама;
  - **рисуется только видимое**: каждый зал, перегородка и холл — отдельная
    группа. Каждый кадр от зала, где стоит зритель, идёт обход по проёмам:
    проём проецируется на экран и пересекается с окном, через которое виден
    текущий зал; пусто — дальше ничего не видно. В дальних залах рисуются
    только работы, попадающие в их проём. Остров ничего не отсекает — лишнее
    иногда рисуется, нужное не теряется: девять поз, снятых с отсечением и
    без, совпадают попиксельно. Неподвижное одного материала (стены, пол,
    потолок, швы, треки, световые линии) при сборке зала сливается в один
    меш, фактура стен и пола идёт по мировым координатам — без швов на
    стыках. Залы собираются по мере надобности: при входе — холл и первые
    залы разделов, дальше — соседние по ходу, по одному за кадр. Работам в
    невидимых залах больше 400 px не грузится.
    Замер в тех же позах, до → после: вызовов отрисовки в холле 412 → 72, в
    первом зале 417 → 193, из середины раздела 242 → 147; треугольников
    35–43 тыс. → 1–9 тыс.; сборка сцены при входе 1136 → 662 мс;
  - **экскурсия** — кнопка «▷ Экскурсия»: камера обходит раздел по кольцу
    (вглубь по левому проходу, обратно по правому) и останавливается у
    каждого художника — сначала у работ на наружной стене, потом у работ
    на острове; если работ на стороне много, остановок несколько, чтобы
    группа помещалась в кадр. Внизу — имя, город, «художник N из M» и
    кнопки ‹ › «Стоп». Из холла экскурсия идёт по разделу, выбранному
    вкладкой, из зала — с ближайшего художника. Любое действие в сцене
    (шаг, поворот, щелчок, колесо, джойстик) её прекращает; пока открыта
    работа или карточка, экскурсия ждёт. В конце раздела — «Экскурсия по
    другому разделу» или «В холл»;
  - **на телефоне** — джойстик слева внизу (вверх — вперёд, вбок — шаг в
    сторону, сила — насколько далеко палец от центра), кнопки шага справа;
    второй палец в это время может водить по сцене и осматриваться.
    **Не во весь экран** вертикальное движение пальца по сцене листает
    страницу (`touch-action: pan-y`), горизонтальное — поворачивает взгляд;
    во весь экран палец снова целиком у зала.
  - **под закреплённой шапкой сайта** — если каталог стоит первым блоком
    страницы, а у сайта шапка `position: fixed`/`sticky` (на Tilda — своя
    шапка «Арт-Ростов», 74 px на телефоне и 82 px на компьютере), каталог
    сам добавляет сверху отступ ровно на ту часть шапки, что на него
    наезжает (`clearFixedHeader` в `catalog.js`), — логотип и заголовок
    не уходят под неё. Шапку ищет в верхней полосе окна; спрятанную на
    время прокрутки — помнит по прежней высоте; перемеряет при загрузке и
    смене размера окна;
  - **метки на полу** (`markers.js`): на компьютере под курсором тёмное
    кольцо с точкой — здесь пол, сюда можно перейти щелчком (у стены и в
    мебели кольца нет); после щелчка или касания пола в точке назначения
    остаётся кольцо цвета акцента, пульсирует в пути и гаснет по приходу.
    На сенсорном экране курсора нет — в зале на полу по осям проходов
    впереди (2.5–13 м, в кадре) до шести бледных колец: пол можно нажать;
  - **надписи — ссылки**: у таблички у работы внизу кнопка «О художнике →»
    (раньше — строка текста); имя художника на стене с подписью
    «О художнике →» открывает его карточку (раньше не нажималось);
    табличка и имя под курсором чуть увеличиваются; имя художника в
    заголовке слева вверху — ссылка на карточку;
  - **меню** — над сценой справа только две кнопки: «во весь экран» и меню
    (☰, крайняя справа). Меню разворачивается колонкой по правому краю:
    круглый значок и подпись — экскурсия, в холл, план залов, художники,
    звук, свет, ссылка на это место, качество изображения, простой режим.
    Звук и свет — переключатели (подпись говорит, что включено), меню
    остаётся открытым; остальные пункты его закрывают. Не влезла колонка
    (телефон горизонтально) — она прокручивается. На iPhone звук страницы
    объявлен «воспроизведением» (`navigator.audioSession`, Safari 17+) —
    беззвучный режим его не глушит. У панелей «Художники», «План»,
    «Качество» своя кнопка ✕; панель открывается под кнопками, пока она
    открыта, джойстик и кнопки шага скрыты, касание сцены её закрывает.
    Во весь экран на iPhone (запасной способ без Fullscreen API: сцена
    переносится в слой поверх страницы) окна работы, карточки и заявки
    открываются внутри этого слоя, поверх сцены; кнопки не заходят под
    «чёлку» и полоску «домой». Поля ввода — 16 px, чтобы iPhone не приближал
    страницу. Сцена переживает разворот:
    проверено на эмуляции iPhone 13 — 390×664 → 844×390 и обратно, холст
    и пропорции камеры подстраиваются, после выхода сцена возвращается на
    место в странице;
  - **бережный режим памяти** — на Android и устройствах с малой памятью
    браузер даёт странице мало видеопамяти, и не поместившиеся текстуры
    рисуются чёрными. Там фактуры помещения уменьшаются при загрузке до
    512 px, атлас превью — вдвое, лимит на крупные картинки — 50 МБ (вместо
    ~270 МБ всего — около 90). Если видеочип не умеет рисовать в формат с
    плавающей точкой, живые отражения выключаются. Простой зал и так
    держит в памяти только ближние работы. Включить принудительно —
    `#artlean` в адресе;
  - **диагностика** — `#artdebug` в адресе страницы: внизу сцены панель с
    моделью видеочипа, памятью, уровнем качества, расходом видеопамяти,
    ошибками WebGL и шейдеров. Скриншот этой панели с проблемного телефона —
    всё, что нужно для разбора;
  - **качество изображения** — кнопка с ползунками над сценой: «Авто»,
    «HD», «SD»; выбор запоминается в браузере (прежние «Высокое» → HD,
    «Среднее» и «Низкое» → SD). HD — объёмное затенение (GTAO: мягкие тени
    в углах, у рам, под островом и кадками), свечение ламп, сглаживание в
    постобработке, тени от рам, плотность пикселей до 2. SD — без
    постобработки, со сглаживанием холста; заранее рассчитанные мягкие тени
    у стыков стена–пол, стена–потолок, у острова и перегородок остаются
    (почти ничего не стоят, а без них зал плоский и серый); на телефоне —
    без лучей спотов и света от экрана (полупрозрачные площади поверх
    кадра, дорогие для мобильного видеочипа); плотность до 2 на телефоне,
    до 1.5 на компьютере. «Авто» стартует с HD на компьютере и SD на
    телефоне.
    **Чёткость подстраивается сама**: цель — 30 кадров/с на телефоне и 45
    на компьютере; по медиане 60 кадров плотность пикселей опускается
    ступенью 0.25 (не ниже 1 на телефоне), а при большом запасе
    поднимается; ступень, где не успели, 20 с не берётся. Когда зритель
    стоит (камера неподвижна полсекунды), кадр рисуется в полной чёткости,
    с первым шагом возвращается рабочая плотность. Смена плотности применяется
    в начале кадра, перед отрисовкой: смена размера холста его стирает, и
    раньше до следующего кадра был виден пустой холст — белая вспышка при
    остановке и начале ходьбы (во весь экран заметнее). HD, не успевающий и на
    пониженной плотности, в «Авто» переходит на SD. На HD тон-маппинг
    применяется ко всему кадру, включая работы: самые светлые места картин
    чуть компрессируются;
  - **без остановок при ходьбе**: скачанные картинки уходят в видеопамять
    по очереди — ближайшие первыми, не больше ~2 МБ за кадр на телефоне
    (~8 МБ на компьютере), а не все пришедшие разом; отражения помещения
    переснимаются по грани куба за кадр (шесть кадров и седьмой —
    фильтрация) вместо шести отрисовок сцены в одном кадре.
    **Шейдеры собираются заранее**, пока виден загрузчик (последние 8 %
    полосы): снимок отражений холла, затем `compileAsync` по всей сцене
    (холл и залы 1–2 каждого раздела) для трёх целей — экран, буфер
    постобработки HD и куб отражений (у каждой свой вариант шейдера) — и
    в двух вариантах света: с площадными светильниками холла и без них
    (когда холл скрыт за стеной, их число в сцене меняется). Раньше это
    были 20–50 сборок шейдеров посреди ходьбы; теперь после показа —
    1–2. Прогрев ждём не дольше 6 с, остальное доделывается в фоне.
    **Залы собираются частями**: следующий зал по ходу — помещение и
    картины одним шагом, мебель тремя (скамьи, потолок, навесное), по
    шагу за кадр; одинаковые детали мебели строятся один раз
    (`Props.G`). Зал, который уже виден, собирается сразу целиком.
    Самый долгий шаг — ~7 мс на компьютере (было 16–30 мс за раз);
  - **маршрут обходит мебель**: отрезок пути по клику, задевающий
    скамью, стойку, кадку или урну (`plan.block`), огибает её через угол с
    запасом 0.5 м (`Nav.detour`) — раньше камера проезжала сквозь скамью
    холла по пути к проёму зала;
  - **рывки в диагностике**: в панели `#artdebug` строка «рывков за
    30 с» — кадры дольше 50 мс, худший и причины по частоте (сборка
    зала, картинки, отражения, отрисовка, шейдеры, видеочип/браузер), и
    сколько шейдеров собрано заранее и за сколько;
  - в холле — кадки с растениями у северной стены;
  - **когда 3D невозможно** — нет WebGL, `gallery.js` не загрузился, пропал
    контекст видеокарты или картинки лежат на чужом домене без CORS (браузер
    не даёт их WebGL) — виджет сам возвращается к CSS-залу. Вариант без CORS
    (`artists.js`) сразу показывает CSS-зал. Проверить CSS-зал можно
    параметром адреса `?hall=css`.
  - **простой режим — по выбору зрителя**: кнопка «Простой режим» есть и в
    загрузчике, и в самой галерее (последний пункт меню). В простом
    зале слева вверху — кнопка «3D-галерея», она возвращает обратно. Выбор
    запоминается в браузере (`localStorage`, ключ `artc-hall`): зашедший в
    простой режим и в следующий раз попадёт в него, пока сам не переключится.
    Кнопка «3D-галерея» не показывается, если браузер 3D не умеет или галерея
    не смогла загрузиться.

  Исходники — `gallery/src/`: `layout.js` (план помещений и проходимые
  области), `world.js` (геометрия по залам, таблички), `visibility.js`
  (отсечение по проёмам), `quality.js` (уровни качества, постобработка),
  `materials.js` (процедурные
  фактуры), `textures.js` (уровни детализации картин), `nav.js` (ходьба и
  маршруты через арки), `tour.js` (экскурсия), `pbr.js` (материалы из фактур),
  `probe.js` (отражения), `lights.js` (споты), `atmosphere.js` (лучи и пыль),
  `props.js` (мебель, оборудование и анимация), `audio.js` (звук),
  `index.js` (сцена и интерфейс). После правок:

  ```bash
  cd catalog/gallery && npm install && npm run build   # → static/artcatalog/gallery.js
  ```

- **Простой зал** (CSS, без WebGL; запасной режим и выбор зрителя) — одна
  длинная стена с работами слева от зрителя (`buildHall` и `wall*` в
  `catalog.js`, стили `.artc-hw*` в `hall.css`):
  - **стена цепочкой**: у каждого художника свой отрезок, соседние стоят под
    углом 12° друг к другу (зигзаг ±6°) — излом и есть граница между
    художниками; второй отрезок чуть темнее первого. Над отрезком крупно
    имя, город и «О художнике →»; перед первым художником — вводный отрезок
    с названием раздела и числом художников и работ, после последнего —
    «Конец раздела» с кнопками «следующий раздел →» и «В начало»;
  - **камера** скользит вдоль стены и смотрит на неё наискосок (36° от
    перпендикуляра): текущая работа крупно в центре, следующие уходят в
    перспективу вправо — по ходу чтения. Расстояние — по размеру сцены
    (полотно около половины меньшей стороны), пересчитывается при смене
    размера (`ResizeObserver`); у излома взгляд поворачивает плавно;
  - **светлый зал**: пол и потолок — градиенты фона сцены, а не
    3D-плоскости; справа дневной свет из проёмов противоположной стены,
    полосы света плывут при ходьбе. Тёмного конца коридора больше нет;
  - **листание**: кнопки ‹ › внизу (с номером работы у художника), клавиши
    ← → ↑ ↓, PageUp/PageDown, Home/End, Enter — открыть текущую; перетаскивание
    стены вбок мышью или пальцем (вертикальный жест листает страницу, во весь
    экран — тоже зал); отпустили — к ближайшей работе, быстрый бросок — к
    следующей; колесо по горизонтали (тачпад) всегда, вертикальное — только
    во весь экран, иначе мышь над залом не могла бы листать страницу;
  - **таблички** под работами: название до 4 строк, имя до 2, длинные
    слова переносятся; стена ниже полотен продлена (`W_FOOT`), плинтус
    рисуется под табличками — проверено по всем 581 табличке: ни одна не
    доходит до плинтуса;
  - **нажатия**: полотно — работа во весь экран, под ней карточка
    художника; табличка, имя на стене и имя в заголовке — карточка.
    «Вернуться в зал» — обратно к той же работе;
  - **поиск** художника — кнопка-лупа сверху: список с фото, поиск и
    указатель по первой букве; далёкого художника показывает сразу, без
    прокрутки мимо сотни работ;
  - **экскурсия** — кнопка ▶︎❚❚ внизу: работы сменяются сами, по 4.2 с,
    любое действие посетителя её прерывает;
  - **во весь экран** — кнопка сверху; где нет Fullscreen API (iPhone), зал
    переезжает в слой поверх страницы;
  - **память**: разметка всех отрезков создаётся сразу, но рисуются только
    ±4 от текущего, картинки грузятся у ±2 и выгружаются дальше ±5 — на
    телефоне в памяти десяток-другой работ, а не сотни.
- **Каталог** — карусель карточек художников.

## Куратор

Виртуальный куратор выставки встречает посетителя и отвечает на вопросы
текстом, в облачке. Голоса нет.

- **Где стоит.** В 3D-галерее — в холле, у входа в «Арт-салон», между
  проёмом и экраном; фигура всегда повёрнута к зрителю, над головой облачко
  «Могу ли я Вам чем-то помочь?» (видно, пока зритель в холле ближе 15 м).
  Позвать её можно и из любого зала — меню ☰ → «Спросить куратора». В
  простом зале — у вступительной стены каждого раздела: это теперь первая
  остановка раздела («Вход в раздел»), камера там чуть дальше, чтобы фигура
  была видна в полный рост, к первой работе расстояние плавно становится
  обычным.
- **Окно вопросов** открывается нажатием на фигуру или облачко. Оно лежит
  внутри сцены, поэтому работает и во весь экран; на телефоне выезжает снизу
  на всю ширину. Приветствие, кнопки-подсказки частых вопросов, поле для
  своего вопроса. Ответ «печатается» за 1–2.5 с (при
  `prefers-reduced-motion` — сразу). Если в вопросе названа фамилия
  художника, под ответом кнопка «Перейти к работам →»: в 3D зритель
  подходит к его первой работе, в простом зале — стена прокручивается к
  нему (с переключением раздела). Жесты, колесо и клавиши над окном по залу
  не водят; Escape закрывает окно.
- **Откуда ответы.**
  - Без `data-curator` — прямо в браузере по `curator/faq.json`: ключевые
    фразы вопроса сравниваются по основам слов («билеты» = «билетов»);
    фамилия художника в вопросе важнее общих ответов (кроме «как купить»):
    «Где работы Шитовой?» — ответ про Шитову (город, сколько работ, раздел)
    и кнопка перехода. Нет совпадений — вежливое «уточните у организаторов».
    `faq.json` берётся запросом — нужен тот же CORS, что и для
    `artists.json` (без него — только приветствие и «уточните у организаторов»).
  - С `data-curator` — запрос к Django-приложению (`POST …/curator/ask/`,
    вопрос, два последних обмена репликами и режим `3d`/`simple`). Сервер
    отвечает готовым ответом, если вопрос явно про него, иначе спрашивает
    нейросеть GigaChat, передавая ей `kb.md`, список участников и подробности о
    художниках, названных в вопросе. Сервер не ответил за 20 с или вернул
    ошибку — ответ из `faq.json` в браузере, посетитель ошибки не видит.
- **Как править ответы.** `curator/faq.json`: `greeting` — приветствие,
  `fallback` — ответ «не знаю», `chips` — какие вопросы показать
  кнопками, `items` — вопросы (`q` — как показать кнопкой, `keys` —
  ключевые фразы, `a` — ответ, `a_simple` — ответ для простого зала, если он
  там другой). `curator/kb.md` — сведения о выставке для нейросети; строки с
  «УТОЧНИТЬ» (цены билетов, часы, парковка, кафе, возраст) нужно заполнить
  у организаторов. Сервер перечитывает оба файла раз в 5 минут —
  перезапуск сайта не нужен.
- **Фигура** — фото из `model/7 (2).jpg`, фон убран открытой моделью
  rembg (birefnet-portrait), край подрезан на пиксель от ореола:
  `curator/figure.webp` (513×1200) и портрет `curator/face.webp`
  (192×192). Согласие модели на использование фото получено.
- **Движение.** Куратор не стоит неподвижно: опускает руку вдоль тела,
  задерживает её и снова кладёт ладонь на бок, слегка переносит вес.
  Ролик сделан нейросетью Wan 2.2 «видео из фото» (пространство
  `zerogpu-aoti/wan2-2-fp8da-aoti-faster` на Hugging Face) из кадра
  `model/anim/start-9x16.jpg` — фигура на ровном светлом фоне. Из ролика
  взяты кадры 1–40 (дальше нейросеть поворачивала голову, и лицо переставало
  быть похожим), фон убран той же rembg, цикл собран «туда-обратно» с
  плавным разгоном и торможением — в разворотах она замирает, шва нет.
  Сборка: `tools/curator-anim.py` (описание — в начале файла). Результат:
  - `curator/idle.mp4` — для 3D: в кадре сверху цвет, снизу прозрачность
    серым; обычное видео H.264 играет везде, включая iPhone, в видеопамяти
    один кадр. Играет, только пока зритель в холле ближе 30 м; вкладка
    скрыта или открыто окно работы — пауза. iPhone в энергосбережении не
    даёт запускать видео сам — тогда фото, и новая попытка после касания сцены;
  - `curator/idle.webp` — для простого зала: анимированный WebP с
    прозрачностью, обычная картинка без скриптов; грузится, когда фигура
    впервые видна.

  Пока ролик не загрузился, при ошибке и при `prefers-reduced-motion` —
  неподвижное фото. Соглашение о кадре (его ждут `gallery/src/curator.js` и
  `catalog.js`): низ кадра — пол, стоящая фигура — 90 % высоты кадра.

## Установка на сайт (арт-ростов.рф)

### 1. Статика

Скопировать папку `static/artcatalog/` в статику Django-проекта так, чтобы файлы
были доступны по адресу `/static/artcatalog/...` (обычно — в каталог из
`STATICFILES_DIRS` + `collectstatic`). Вместе с ней уходит и 3D-галерея
(`gallery.js`). После того как на месте все картинки, соберите атлас превью:
открыть `tools/build-atlas.html`, указать `https://арт-ростов.рф/static/artcatalog/`,
положить скачанные `atlas.json` и `img/atlas/*` в ту же папку.

### 2. Приложение заявок

1. Скопировать `django/artcatalog/` в проект сайта.
2. В `settings.py`:
   ```python
   INSTALLED_APPS += ["artcatalog"]

   # необязательные настройки (значения по умолчанию):
   ARTCATALOG_LEAD_EMAIL = "ads@donexpocentre.ru"  # получатель заявок
   ARTCATALOG_RATE_LIMIT = 5        # заявок с одного IP…
   ARTCATALOG_RATE_WINDOW = 3600    # …в час
   ```
3. В корневом `urls.py` — строго **вне** `i18n_patterns` (иначе адрес станет
   `/ru/api/...`, а виджет обращается к `/api/...`):

   Django 2.0+:
   ```python
   from django.urls import path, include
   urlpatterns = [
       path("api/artcatalog/", include("artcatalog.urls")),
       # ... остальные url
   ]
   ```

   Django 1.8–1.11 (старые django CMS-проекты):
   ```python
   from django.conf.urls import include, url
   urlpatterns = [
       url(r"^api/artcatalog/", include("artcatalog.urls")),
       # ... остальные url
   ]
   ```
   Функции `path()` в Django 1.8 нет — использование её в urls.py уронит весь сайт.
4. Убедиться, что на сайте настроена почта (`EMAIL_HOST`, `DEFAULT_FROM_EMAIL` и т. д.) —
   приложение использует стандартный `django.core.mail.send_mail`.
5. (Рекомендуется) добавить файловый лог заявок — резервная копия на случай сбоя почты:
   ```python
   LOGGING["loggers"]["artcatalog.leads"] = {
       "handlers": ["artcatalog_file"], "level": "INFO",
   }
   LOGGING["handlers"]["artcatalog_file"] = {
       "class": "logging.FileHandler", "filename": "/var/log/site/artcatalog-leads.log",
   }
   ```

Миграции не нужны — приложение не создаёт моделей.

**Куратор** (необязательно) подключается тем же `include("artcatalog.urls")` —
адрес `/api/artcatalog/curator/ask/`. Без настроек он отвечает готовыми
ответами; нейросеть включается ключом GigaChat:

1. Зарегистрироваться на developers.sber.ru → GigaChat API (тариф Freemium для
   физлиц), создать проект, в нём — «Ключ авторизации».
2. В `settings.py`:
   ```python
   ARTCATALOG_GIGACHAT_KEY = "…"            # ключ авторизации (Base64), только здесь, не в браузере
   ARTCATALOG_GIGACHAT_SCOPE = "GIGACHAT_API_PERS"
   ARTCATALOG_GIGACHAT_CA = "/etc/ssl/certs/russian_trusted_root_ca.pem"   # если сервер не доверяет НУЦ Минцифры
   ARTCATALOG_CORS_ORIGINS = ["https://monthly-delicious-mirror.tilda.ws", "https://xn----7sbh1cajbjfe.xn--p1ai"]
   # необязательно:
   ARTCATALOG_CURATOR_NAME = ""            # имя, если куратор представляется
   ARTCATALOG_CURATOR_RATE = 20            # вопросов с одного IP…
   ARTCATALOG_CURATOR_WINDOW = 3600        # …в час
   ARTCATALOG_CURATOR_DAILY = 3000         # вопросов к нейросети в сутки на весь сайт
   ARTCATALOG_CURATOR_DIR = "…/static/artcatalog/curator"   # если STATIC_ROOT другой
   ARTCATALOG_ARTISTS_JSON = "…/static/artcatalog/artists.json"
   ```
   Корневой сертификат: https://www.gosuslugi.ru/crt → «Корневой сертификат»
   (PEM). Кеш Django (`CACHES`) нужен любой, кроме `DummyCache`: в нём счётчики
   ограничений и ответы нейросети на сутки.
3. В контейнер виджета добавить `data-curator="https://<сайт>/api/artcatalog/curator/"`.
4. Проверка: `curl -X POST -H "Content-Type: application/json" -d '{"q":"Расскажите про Шитову"}' https://<сайт>/api/artcatalog/curator/ask/`
   → `{"answer": "…", "source": "ai"}`; `"source": "faq"` — готовый ответ,
   `"fallback"` — нейросеть недоступна (подробности в логе `artcatalog.curator`).

### 3. Snippet

Вставить содержимое `snippet.html` в Snippet на нужной странице.
Перед вставкой заменить `data-policy` на реальную ссылку на политику обработки
персональных данных сайта.

### 4. Проверка

1. Открыть страницу — каталог отображается, карусель листается (стрелки, свайп, клавиатура).
2. Вкладка «Виртуальный зал»: загрузчик с песочными часами и процентами, затем
   холл, в проёмах видны залы. Пройти в зал, щёлкнуть

   галерею сразу у работы). В консоли (F12) нет ошибок; без WebGL или с

3. Открыть художника, открыть работу в лайтбоксе.
4. Нажать «Хочу купить», отправить тестовую заявку с реальным телефоном/email —
   письмо должно прийти на ads@donexpocentre.ru.
5. Куратор: в холле у входа в «Арт-салон» стоит фигура с облачком; нажать —

6. Проверить мобильную версию (320–480 px): в галерее джойстик слева внизу,
   кнопки над сценой значками, «во весь экран» переживает поворот телефона.

## Как добавить много художников сразу

Исходники — папка с подпапками, по одной на художника/галерею: только
фотографии работ, имя папки — что-то похожее на ФИО или название. Текст про
всех берётся из **одного общего документа Word** (по одному — на художников
и на галереи; таблица, одна строка — одна запись: имя, город, контакты,
биография). Запись общего списка находится по совпадению значимых слов с
именем папки (фамилия, название студии — общие слова вроде «галерея» или
«студия» не считаются, иначе разные галереи путаются друг с другом). Если
для кого-то общего текста нет — как и раньше, можно положить файл `.docx`
или `.xlsx` прямо в его папку. Если художники разложены по папкам разделов
(«Арт-салон», «Галереи»), разделы подхватятся сами, и совпадение по каждому
разделу ищется в своём общем списке.

Что берётся из документа: имя, город, текст о художнике (все абзацы, а не
только первый) и ссылки на соцсети — в том числе бывшие без «http://», просто
доменом или «@ником» под понятной подписью («ВК:», «ТГ:» и т.п.). Ссылки на
Instagram пропускаются — сервис признан экстремистским и запрещён в РФ.
Портрет автора узнаётся по имени файла: если в нём есть слово из имени
художника или слово «портрет».

**Способ без CORS.** Если статику раздаёт сервер без заголовков CORS, в блоке
вставки подключён `artists.js` — и тогда `artists.json` виджет не читает вовсе
(найдя `window.ARTCATALOG_DATA`, он за json уже не идёт). Кнопка «Скачать
artists.js» отдаёт те же данные в нужном виде. Если `artists.json` уже собран
раньше, пересчитывать картинки не нужно: на той же странице есть отдельный
выбор файла, который переделывает готовый `artists.json` в `artists.js`.

**Картинки из каталога.** Если вдобавок выбрать `catalog-images.zip`, недостающее
берётся из печатной версии: портрет, которого нет среди файлов участника, и
работы, которых не хватает (например, присланные в `.tif` — браузер их не
открывает). Подставляется только недостача: если файлов столько же, сколько
работ на странице, значит они просто не опознались, и дублей не будет.

**Портрет автора.** Если рядом положить `catalog-map.json` (см.
`tools/catalog-pdf/`), портрет определяется по печатному каталогу, а не по
имени файла: в печатной версии портрет стоит левее всех прочих изображений
страницы, и нужный снимок опознаётся по отпечатку даже после пересжатия.
Оттуда же берётся порядок работ. Участники, которых в печатном каталоге нет,
пропускаются и перечисляются в журнале отдельно. Без этого файла портрет
по-прежнему ищется по имени файла.

**Личные телефоны и почта художников не попадают в каталог никогда.** Защита
двухслойная: сначала вырезается всё под подписями «Тел.:» и «Почта:», а
потом готовый текст ещё раз прочёсывается безусловно — на случай, если
номер записан без подписи, под незнакомой («Ватсап:», «Контакты:») или
просто посреди предложения. Годы, размеры работ, номера домов и адреса
соцсетей с длинными числовыми id при этом не страдают. Если второй слой
что-то вырезал, в журнале появится отметка «вырезан контакт без подписи» —
это повод заглянуть в текст. В каталоге публикуются только соцсети и сайты.

**Без установки чего-либо:** скачайте `tools/prepare.html` (кнопка *Download raw
file* на странице файла в GitHub) и откройте двойным щелчком — это обычная
страница, ей не нужен ни сервер, ни интернет. Выберите общие списки (.docx),
перетащите папку с фотографиями. Всё считается на месте, файлы никуда не
уходят; на выходе — архив с картинками и готовый `artists.json`. HEIC-снимки
с iPhone браузер открыть не может: такие файлы будут перечислены отдельно, их
нужно заранее пересохранить в JPEG.

После прогона в журнале на странице видно: сколько папок нашли пару в общем
списке, какие папки остались без пары (текст возьмётся из файла в папке или
из её названия — впишите вручную) и какие записи списка остались без папки с
фото (не попадут в каталог — либо папки не хватает, либо имя папки слишком
не похоже на запись). Проверьте руками: названия работ (берутся из имён
файлов), биографии и портрет автора — если опознать портрет не удалось,
инструмент берёт первое фото и предупреждает об этом.

**Если есть Python** — командная строка (`tools/prepare-artists.py`) пока
понимает только старый формат: одна папка — один `.docx`/`.xlsx` внутри неё
(вариант из общего списка на весь зал она не читает). Если исходники — в
общем документе, пользуйтесь `prepare.html`.

```bash
pip install Pillow openpyxl pillow-heif        # heif — если есть фото с iPhone
python3 tools/prepare-artists.py "путь/к/папке/с/художниками" --zip
```

На выходе: `static/artcatalog/img/<slug>/…`, `artists.generated.json` с
готовыми записями и `artcatalog-img.zip` для заливки на сервер.

**Оригиналы в репозиторий класть не нужно.** Снимок работы на 14 МБ на сайт
всё равно не попадает — посетитель видит копии по 400/800/1600 пикселей
(60–250 КБ). Картинки живут на сервере в `/home/develop/donexpo/static/artcatalog/img/`,
в git хранятся только код и `artists.json`.

## Инструкция для контент-менеджера: как добавить одного художника

1. Подготовить изображения (WebP + JPEG с одинаковыми именами):
   - `avatar.webp/.jpg` — квадратное фото автора, 400×400;
   - для каждой работы три размера: `workN-400.*`, `workN-800.*`, `workN-1600.*`
     (число — максимальная сторона в пикселях).
   Быстрее всего — прогнать исходники тем же способом, что и существующие
   (Pillow: `im.thumbnail((size, size))`, сохранить в WebP quality 80 и JPEG quality 82).
2. Положить их в `static/artcatalog/img/<slug>/` (slug — латиницей, например `ivanov`).
3. Добавить запись в `static/artcatalog/artists.json` в массив `artists`:
   ```json
   {
     "id": "ivanov",
     "name": "Иванов Иван Иванович",
     "city": "Ростов-на-Дону",
     "bio": "Краткая биография (до 500 знаков)…",
     "links": [{ "label": "ВКонтакте", "url": "https://vk.com/…" }],
     "avatar": "img/ivanov/avatar.webp",
     "section": "art-salon",
     "works": [
       {
         "title": "Название работы (можно оставить пустым)",
         "thumb": "img/ivanov/work1-400.webp",
         "medium": "img/ivanov/work1-800.webp",
         "full": "img/ivanov/work1-1600.webp",
         "w": 1600, "h": 1200
       }
     ],
     "order": 6
   }
   ```
   `section` — раздел выставки (id из списка `sections`), `w`/`h` — размеры
   исходного изображения в пикселях: по ним 3D-галерея вешает работу в
   правильных пропорциях (без них — квадрат). Инструменты `tools/` заполняют
   оба поля сами.
   Поле `order` задаёт место в карусели. В контактах публикуются **только соцсети** —
   личные телефоны и email художников в JSON не вносить. Виджет и сам не покажет
   ссылку с `mailto:` или `tel:`: в `links` отрисовываются только адреса на
   `http(s)://`, всё остальное молча пропускается.
4. Выполнить `collectstatic` (если статика раздаётся из `STATIC_ROOT`) и обновить страницу.
5. Пересобрать атлас превью 3D-галереи (`tools/build-atlas.html`, см. выше) и
   залить `atlas.json` и новые `img/atlas/*`. Без этого новая работа в галерее
   всё равно появится, но издалека будет видна пустой рамой, пока не подгрузится.
   Залы и их порядок пересчитываются сами — править ничего не нужно.

## Как это работает

- 3D-галерея — отдельный `gallery.js` (исходники в `gallery/`, three.js внутри
  сборки, внешних зависимостей нет). `catalog.js` грузит его по кнопке «Войти в
  галерею» и передаёт ему данные и функции открытия работы, карточки и формы
  заявки; заявки идут тем же путём, что и из карусели.
- `catalog.js` загружает `artists.json`, строит карусель и все модальные окна.
  Стили изолированы префиксом `.artc-`, глобальных селекторов нет.
- Форма «Хочу купить»: при открытии виджет делает GET к эндпоинту (это выставляет
  csrf-cookie), при отправке — POST JSON с заголовком `X-CSRFToken`.
- Защита от спама: скрытое honeypot-поле + rate limit по IP на сервере. CAPTCHA нет
  намеренно (см. ТЗ).
- Письмо уходит на `ARTCATALOG_LEAD_EMAIL` (по умолчанию ads@donexpocentre.ru),
  каждая заявка дублируется в лог `artcatalog.leads`.
