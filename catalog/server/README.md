# Размещение каталога на собственном сервере

Вариант вместо CDN jsDelivr: файлы лежат у вас, страница на Tilda берёт их
с вашего домена. Так надёжнее — нет зависимости от внешнего сервиса
(у части российских провайдеров jsDelivr периодически недоступен), а
обновление контента больше не требует правки кода вставки.

## Что заливать и куда

Скопируйте по SFTP (WinSCP) **всю папку** `catalog/static/artcatalog/`
целиком, сохранив структуру подпапок:

```
/home/develop/donexpo/static/artcatalog/
├── catalog.js
├── catalog.css
├── hall.css
├── artists.json
├── fonts/parangon.woff2
└── img/
    ├── logo.webp, logo.png
    ├── volvich/     avatar.*, work1-400.*, work1-800.*, work1-1600.* …
    ├── dzhakhaeva/  …
    ├── zhegulova/   …
    ├── larev/       …
    └── masterskaya/ …
```

Всего около 150 файлов, ~16 МБ. В WinSCP включите бинарный режим передачи
(Options → Preferences → Transfer → Binary) — иначе шрифт и изображения
могут побиться. Права: файлы 644, папки 755.

## Что настроить на сервере (обязательно)

Каталог вставляется в страницу на **другом** домене (Tilda), поэтому
браузер считает эти файлы сторонними и по умолчанию блокирует часть из них.
Без настройки заголовков **каталог не откроется вообще**: запрос
`artists.json` будет отклонён, вместо зала посетитель увидит сообщение об
ошибке, а фирменный шрифт не применится. Это проверено — не опционально.

1. **Разрешающий заголовок CORS** для папки `/static/artcatalog/`:
   готовый фрагмент конфигурации — `nginx-artcatalog.conf` (для Apache
   те же заголовки задаются в `.htaccess` директивой
   `Header set Access-Control-Allow-Origin "*"`).
2. **HTTPS**. Страница Tilda работает по https; файлы, запрошенные по http,
   браузер заблокирует как «небезопасное содержимое».
3. **Типы файлов** — `.webp` и `.woff2` должны отдаваться как `image/webp`
   и `font/woff2` (в свежих nginx это уже так, в конфиге продублировано).
4. **Сжатие** gzip для `.js`, `.css`, `.json` — код каталога ужимается
   с 116 КБ до примерно 31 КБ.

Если статику раздаёт не nginx, а сам Django (`DEBUG = True` или
`whitenoise`), заголовки добавляются на его стороне; лучше вынести раздачу
на nginx — он отдаёт файлы быстрее и не занимает процессы приложения.

## Проверка после заливки

1. Откройте в браузере `https://ваш-домен/static/artcatalog/artists.json` —
   должен показаться список художников.
2. Проверьте заголовок:
   ```bash
   curl -I https://ваш-домен/static/artcatalog/artists.json | grep -i access-control
   ```
   Ожидается строка `access-control-allow-origin: *`.
3. Вставьте блоки `embed-head.html` и `embed-t123.html` (заменив домен) и
   опубликуйте страницу.
4. Откройте страницу, нажмите F12 → Console: должна появиться строка
   `[artcatalog] версия …` и не быть красных сообщений про CORS.

## Обновление каталога

Теперь проще, чем с CDN: **перезалить изменённые файлы** — и всё.
Код вставки на Tilda менять не нужно, публиковать страницу заново тоже.

- новые художники или тексты → `artists.json`;
- новые работы → изображения в `img/<slug>/` + запись в `artists.json`
  (формат описан в `../README.md`);
- правки виджета → `catalog.js`, `catalog.css`, `hall.css`.

Код и данные кешируются 5 минут, картинки и шрифт — 30 дней (у них
неизменные имена). Если правка нужна мгновенно — обновите страницу с
Ctrl+Shift+R или временно уменьшите `expires` в конфиге.

## Что это меняет по сравнению с CDN-вариантом

| | jsDelivr | свой сервер |
|---|---|---|
| Доступность | зависит от внешнего сервиса и провайдера | под вашим контролем |
| Обновление контента | коммит + замена хеша в двух блоках | перезалить файл по SFTP |
| Скорость первой загрузки | глобальная сеть узлов | один ваш сервер (для аудитории из России разницы почти нет) |
| Требует настройки | нет | CORS-заголовок, HTTPS, gzip |

Оба варианта поддерживаются одним и тем же кодом — отличаются только
адреса в блоках вставки. Файлы для CDN-варианта остались в `../tilda/`.

## Заявки «Хочу купить картину»

Сейчас их принимает попап-форма Tilda (см. `../tilda/README.md`) — это
работает и не требует сервера. Раз сервер есть, при желании заявки можно
принимать своим приложением: готовое лежит в `../django/artcatalog/`,
тогда в блоке T123 вместо `data-tilda-popup` указывается
`data-endpoint="https://ваш-домен/api/artcatalog/lead/"`. В этом случае
эндпоинту тоже нужны CORS-заголовки, причём с явным доменом страницы и
`Access-Control-Allow-Headers: Content-Type`.
